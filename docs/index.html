Project Overview

Problem statement

Most Kickstarter campaigns fail. The signals available before launch — the wording of the title, the funding goal, the category, the country, and the campaign duration — are mixed in type: some are free text, others numeric and categorical. The challenge is to combine these unlike inputs into a single model that estimates a campaign's chance of being funded, using only information known at launch.

Objective

Build a leakage-safe, reproducible pipeline that treats this as a binary classification problem (successful vs failed), fuses text and tabular features into one matrix, trains a baseline classifier, and evaluates it honestly against a majority-class baseline. The goal for the team is as much about understanding each stage as shipping it — every member implements the full pipeline in their own repository.

04

Challenges & Leadership

Technical challenges

Interpreting high-scoring TF-IDF tokens
After vectorizing, the top-weighted words weren't obviously related to funding success. Resolved by ranking coefficients by modality and reading them alongside the tabular signals, which showed text is a weak-but-real signal on its own.
Feature dimensionality
TF-IDF plus one-hot encoding pushed the feature space into the thousands. Resolved by capping TF-IDF at 2,500 features (min_df=2) and keeping everything sparse instead of dense.
Merging text and tabular matrices
Combining a sparse text matrix with a tabular matrix via a plain horizontal stack was confusing and error-prone. Resolved by using scipy.sparse.hstack with a shared split-id file to guarantee row alignment.
Model accuracy ceiling · open
The baseline sits around 0.69 accuracy / 0.57 F1 — real but limited. This is the active problem: improving the metrics with faculty guidance is the immediate next priority.

Leadership challenges

Keeping people on track through busy schedules
Members were juggling hackathons and internships. Resolved by keeping each person's scope small, clear, and self-contained so the project never became a burden on top of their other commitments.
Maintaining a shared pace
With everyone working in separate repos it's easy to drift apart. Resolved by the teach-back model — regular discussions where each owner explains their topic keep the whole team aligned on the same stage.
